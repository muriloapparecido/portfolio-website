Overview

The Codebase Q&A Agent is a local RAG (Retrieval-Augmented Generation) system that lets you ask natural language questions about any codebase and get cited, file specific answers. Point it at a local repository, let it ingest the source files, then ask questions like "where is the authentication logic?" or "how does the save function work?" and it returns answers with exact file paths and line numbers. Built from scratch without LangChain, the system implements a custom chunking pipeline, hybrid semantic and keyword search, and streaming ingestion with real-time progress via Server-Sent Events.

Features

  • Multi-repository support — add multiple repositories and switch between isolated chat sessions, each with its own conversation history.
  • Real-time ingestion progress — streaming progress bar powered by Server-Sent Events, with cancel support mid-ingest.
  • Hybrid search — semantic vector similarity and exact keyword matching run in parallel, merged via a score based ranking system.
  • Query rewriting — an LLM-based rewriter converts natural language questions into code focused search queries before retrieval.
  • Cited answers — every response references the source file and line numbers the answer was derived from.
  • Configurable ingestion — adjust supported file extensions and skipped directories per session, then re-ingest with one click.

How It Works

  • Ingestion: Walks the repository file tree, chunks source files into overlapping 40-line segments, and stores them with file path and line number metadata in a local ChromaDB vector database.
  • Query rewriting: The user's natural language question is rewritten into a code-focused search phrase using GPT-4o-mini before retrieval.
  • Hybrid retrieval: Semantic vector search and exact keyword matching on camelCase identifiers run in parallel. Chunks found by both methods receive a higher score and rank first.
  • Answer generation: The top-ranked chunks are passed as context to GPT-4o-mini, which returns a cited answer grounded only in the retrieved code.

Why Hybrid Search?

Semantic search alone fails for exact code identifier lookups. Function names like handleCreateColumn or handleIngest have no natural language meaning that embeddings can bridge to from a user's question. During development, the target chunk consistently failed to appear in the top 20 semantic results despite being correctly indexed. Adding keyword matching as a parallel retrieval path and boosting chunks found by both methods fixed this retrieval failure entirely.

Technology Stack

  • Backend: Python, FastAPI
  • Vector Database: ChromaDB (local persistent mode)
  • LLM: OpenAI GPT-4o-mini
  • Frontend: React, TypeScript, Vite
  • Streaming: Server-Sent Events (SSE)

Running Locally

This tool runs locally so each user points it at their own codebase using its absolute path and supplies their own OpenAI API key. Clone the repository, install backend dependencies with pip install -r requirements.txt, add your key to a .env file, start the FastAPI server, then run the React frontend with npm run dev. Full setup instructions are in the README.
